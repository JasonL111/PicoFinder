# 故障排查

| 现象 | 检查与处理 |
|---|---|
| BOOTSEL 无磁盘/串口 | 使用 USB 数据线和直连端口；按住 BOOTSEL 插入；确认是 Pico 2 W |
| import bluetooth 失败 | 刷 RPI_PICO2_W 官方 1.27.0 稳定 ARM 镜像，非其他 Pico 型号 |
| 上电不运行 | 四个文件在 MicroPython 根目录，主入口名 main.py；Ctrl-D 或断电重插；看 REPL traceback |
| USB 串口忙 | 关闭另一个 Thonny / mpremote 会话；Linux 检查串口用户权限，Windows 核对 COM 号 |
| ID 每次变 | 检查是否擦除文件系统/删除 device_id.txt；正常升级只覆盖四个源码文件 |
| identity 损坏 | 不会静默换 ID；手动修正为 8 位非零十六进制，或在 config.py 指定唯一 ID |
| 日志成功但手机无标签 | 日志不证明 RF；关闭模拟模式、授权附近设备+精确位置、开启蓝牙与位置开关；距标签约 1 米；检查数据体版本/UUID |
| 系统配对列表找不到 | 正常；这是不可连接广播，不需要配对，使用本 App 或原始 BLE 扫描工具 |
| 第三方扫描器有而 App 没有 | 查看 Service Data AD 0x21 和 16 字节 UUID 顺序；不要使用 UUID List filter；核对协议 v1 精确 8 字节 |
| 扫描失败/频率限制 | 停止频繁点击；等至少 30 秒；关闭其他扫描 App，必要时重开蓝牙；App 不无限自动重试 |
| 返回 App 后无更新 | 前台设计：进入后台/锁屏/重建后停止；返回后主动开始，2 分钟也会自动停止 |
| 权限被永久拒绝 | 点“权限设置”，附近设备允许、位置选“使用期间+精确”；返回后点开始 |
| RSSI/距离剧烈变化 | 固定手机与标签朝向、远离金属/人体，观察几秒趋势，1 米校准；n 按环境调整，别把 RSSI 当精密测距 |
| 校准失败 | 先开始扫描、固定相距约 1 米至少 8 秒，需要 >=12 个有效样本和 >=6 秒跨度；不稳定时旧值不会覆盖 |
| 删除后标签又出现 | 只删本机数据，仍在广播的标签会被重新发现；若需隐藏先拔掉该标签 USB 电源 |
| 两块标签合并成一个 | Device ID 冲突，给其中一块设置不同 ID；MAC 不参与身份识别 |
| 从不同来源安装 Debug APK 失败 | 不同电脑/CI 的 debug 签名可能不同；优先一直用同一来源。若卸载后重装，会丢失本机名称和校准，请先记录参数 |
| 距离变成 — | 扫描已停止、尚无新包或默认 5 秒未收到包；不会显示伪实时陈旧距离 |
| 构建下载失败 | 查看代理/CA/域名，允许 Google Maven、Maven Central、Gradle 官方下载；不能关闭 TLS 或校验和 |
| Android Studio 同步失败 | 使用 JDK 21、SDK 36、仓库 Wrapper；不要使用系统任意 Gradle；路径含 SDK 时 local.properties 不提交 |

真实设备测试需记录手机型号/Android 版本、Pico MicroPython 版本、实际 ID、权限状态、
USB 日志与 Service Data 原始十六进制。日志不要包含个人凭据；项目本身没有任何必需 API Key。
